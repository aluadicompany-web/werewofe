# ลูกสมุนใน Classic 6 คน และหน้าผลส่วนตัว

ชุด 6 คนปรับตามผลเล่นจริงและคำขอผู้ใช้: **หมาป่า 1, ลูกสมุนหมาป่า 1, ผู้หยั่งรู้ 1, หมอ 1, ชาวบ้าน 2** ใช้แทนชาวบ้านหนึ่งคน ชุด 7–12 คนและ Advanced คงเดิม ไม่มีค่า Environment ใหม่หรือค่าใช้จ่ายบริการเพิ่ม

## กติกาลูกสมุน

- ลูกสมุนรู้ตัวหมาป่าจริงผ่านข้อมูลส่วนตัว แต่หมาป่าไม่รู้ตัวลูกสมุนขณะยังมีชีวิต
- ไม่มีพลังคืน ไม่ร่วมลงคะแนนฆ่า ไม่มีแชตฝูง และไม่เห็นรอยเท้าหรือแผนโจมตีของฝูง
- หมาป่าเลือกฆ่าลูกสมุนได้ หมอปกป้องลูกสมุนได้ตามกติกาปกติ การฆ่าพลาดเป็นส่วนที่ตั้งใจให้เกิดได้
- ผู้หยั่งรู้ตรวจว่า **ไม่ใช่หมาป่า / 👍** ซึ่งไม่รับรองว่าอยู่ทีมหมู่บ้าน
- ชนะร่วมกับทีมหมาป่าแม้ลูกสมุนถูกกำจัดไปแล้ว แต่หากหมาป่าจริงตายหมด ลูกสมุนแพ้แม้ยังมีชีวิต
- **ไม่นับเป็นหมาป่าใน parity:** หมาป่า 1 + ลูกสมุน 1 + คนอื่น 2 ยังไม่จบ แต่หมาป่า 1 + ลูกสมุน 1 เป็นสองคนสุดท้ายจบด้วยทีมหมาป่าชนะ
- เปิดบทบาทผู้ตายและตอนจบเหมือน Classic เดิม เมื่อรู้ตัวหลังตายจึงเป็นข้อมูลสาธารณะตามกติกา
- GM ร่วมเล่นเลือก Minion ได้เฉพาะชุด 6 คน หรือเลือกสุ่มตามปกติ GM ผู้คุมนอกเกมไม่รับบทบาท

ในโค้ด `ROLES[role].team` ระบุทีมชนะ ส่วน `countsAsWolf` และ `isWolf` ระบุหมาป่าจริงสำหรับการโจมตี/แชต/parity โดยเฉพาะ `knowsWolves` ใช้กับ projection ทางเดียว ไม่ใช้ให้สิทธิ์แชตหรือโจมตี วิธีนี้ป้องกันการเผลอนับลูกสมุนเป็นหมาป่าหรือเปิดเผยลูกสมุนให้ฝูง

## แถบบทบาทด้านบน

หลังเริ่มแมตช์ แถบ **บทบาทในแมตช์นี้** เหนือกระดานบอกชื่อและจำนวนบทบาทตั้งต้น ไม่จับคู่กับชื่อหรือที่นั่ง ไม่ลดจำนวนเมื่อมีผู้ตาย/ถูกเตะ และแสดงเหมือนกันแก่ผู้เล่นทุกคนและผู้คุม ห้องรอใช้ชุดบทบาทในส่วนตั้งค่าเดิม

## WIN / LOSE / DRAW

เซิร์ฟเวอร์ส่ง `me.outcome` หลังเข้าช่วง result/ended เท่านั้น:

- สมาชิกทีมที่ชนะเห็น **WIN** แม้ตัวเองตายแล้ว รวมลูกสมุนเมื่อหมาป่าชนะ
- สมาชิกทีมที่แพ้เห็น **LOSE** แม้ตัวเองยังมีชีวิต รวมลูกสมุนเมื่อหมาป่าตายหมด
- หากไม่มีผู้รอดชีวิต เห็น **DRAW** ทุกคน
- Host/GM นอกแมตช์ไม่มีทีม จึงไม่ขึ้น WIN/LOSE ปลอม แต่ยังอ่านผลรวมจากกระดานได้
- ไม่แสดงผลก่อนคลี่คลายพลังแม่มด/นายพรานครบ

กด **ปิดผลการแข่งขัน**, แตะข้อความ/พื้นหลัง หรือกด Escape เพื่อปิด หลังปิดยังเห็นผลรวมและบทบาททั้งหมดบนกระดาน การปิดไม่สั่ง rematch/เปลี่ยนเฟส และไม่เปิดซ้ำเมื่อมีข้อความใหม่ เปลี่ยนจาก result เป็น ended หรือรีเฟรชแท็บเดิม บันทึกเฉพาะ game UUID ที่ปิดล่าสุดใน sessionStorage ไม่มีรหัส GM/ข้อมูลคำสั่งเพิ่ม เมื่อเกมใหม่จบจะขึ้นผลใหม่

## วิธีทดลอง

1. สร้างห้อง Classic ให้มีผู้เล่น 6 คน หรือใช้ GM เติมให้ครบ 6 คน
2. ดูแถบบทบาทหลังเริ่ม: หมาป่า ×1, ลูกสมุน ×1, ผู้หยั่งรู้ ×1, หมอ ×1, ชาวบ้าน ×2
3. ทดลอง Minion ในห้อง GM โดยเลือกโรลก่อนเริ่ม ปิด inspector หากต้องการดูข้อมูลแบบลูกสมุนปกติ ผู้เข้าห้องปกติจะไม่รับ debugger ของ GM
4. ตรวจผลผู้หยั่งรู้และการโหวต เมื่อเกมจบแต่ละฝ่ายต้องเห็นคำตรงกับทีมชนะ ไม่อิงว่าตัวเองยังมีชีวิตหรือไม่
5. ปิดผลด้วยปุ่ม/แตะ/Escape แล้วรีเฟรชเพื่อยืนยันว่าไม่เปิดซ้ำ เกมถัดไปต้องเปิดผลใหม่ตามปกติ

`npm test` ตรวจชุดบทบาท ความรู้ทางเดียว สิทธิ์คืน/แชต parity ผลส่วนตัว และ Socket.IO/reconnect จริง `npm run test:minion` ตรวจ static frontend แยก backend หลาย browser contexts รวม WIN/LOSE คนละทีม ลูกสมุนตายแล้ว WIN, ลูกสมุนยังอยู่แล้ว LOSE, ปิด/รีเฟรช/แมตช์ใหม่, roster ไม่เปิดเผยชื่อ, DRAW จากพิษและหมาป่าพร้อมกันผ่าน resolver จริง และหน้าจอ desktop/mobile

คำสั่ง browser รับ `PLAYTEST_BASE_URL` สำหรับทดสอบโดเมนที่ deploy แล้วได้ (สร้างเฉพาะห้อง QA ของตัวเอง) ส่วนกรณี DRAW ที่ใช้ clients เพิ่มสำหรับจัดสถานการณ์จะรันเฉพาะ local ไม่มี test endpoint หรือการฉีดผลลัพธ์เข้า production

ชุดนี้ยังต้องสะสมผลเล่นจริงเพื่อประเมินสมดุล โหวตเสมอ 2–2 ยังใช้ runoff เดิม ไม่เปลี่ยนกติกาโหวตและไม่รับรอง win rate จากบอทสุ่ม
