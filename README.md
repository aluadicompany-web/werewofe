# MOONFALL — Werewolf Online

เกมเบราว์เซอร์ภาษาไทยสำหรับผู้เล่นจริง **6–12 คนต่อห้อง** ไม่ต้องมีผู้ดำเนินเกม สร้าง/เข้าห้องด้วยรหัสหรือแชร์ลิงก์เชิญ รองรับเมาส์และคีย์บอร์ด ใช้ Node.js + Socket.IO ตัดสินกติกาที่เซิร์ฟเวอร์ และแยกหน้าเว็บ static สำหรับ Cloudflare Pages หรือ Netlify

## เริ่มในเครื่อง

Node.js >=22 (ตรวจบน Node.js 24)

```sh
npm ci --cache /workspace/.npm-cache
npm start
```

เปิดเบราว์เซอร์ที่ host ของเครื่องและพอร์ต `3000` เซิร์ฟเวอร์ฟัง `0.0.0.0` เปลี่ยนได้ด้วย `PORT` ใช้ `npm run dev` ระหว่างพัฒนา ไม่มีฐานข้อมูลหรือ API key ที่ต้องใช้ในเครื่อง ฟอนต์และ Socket.IO client เสิร์ฟในเครื่อง ไม่เรียก CDN

## ลองเล่น

1. กรอกชื่อ สร้างห้อง แล้วกด “ลิงก์เชิญ” หรือคัดลอกรหัสให้เพื่อน
2. ผู้รับเปิดลิงก์ รหัสห้องจะกรอกให้ กรอกชื่อแล้วเข้าร่วม แต่ละคนใช้แท็บ/เบราว์เซอร์ของตัวเอง ไม่ duplicate แท็บที่อยู่ในห้องแล้ว เพราะอาจคัดลอก sessionStorage
3. เจ้าของห้องเลือกโหมดและความเร็ว ทุกคนกดพร้อม Classic เริ่มที่ 6–12 คน / Advanced ที่ 9–12 คน คนที่ 13 ถูกปฏิเสธ
4. เปิดดูบทบาท กลางคืนเลือกเป้าหมายแล้วกดยืนยัน เปลี่ยนได้จนหมดเวลา; กลางวันคุยและคลิกการ์ดเพื่อโหวตทันที ไม่ต้องยืนยันซ้ำ (รวมปุ่มงดออกเสียง) นับผลเมื่อหมดเวลา
5. คะแนนเสมอมีโหวตรอบสอง นายพรานมีหน้าต่างยิงเมื่อถูกฆ่าหรือประหาร เมื่อจบเกมเปิดเผยทุกบทบาทและเล่นใหม่ได้

ช่วงโหวตและโหวตรอบสอง เมื่อคลิกโหวตแล้วจะเห็นเครื่องหมายถูกกลางการ์ดของผู้ที่คุณโหวตให้ **เฉพาะคุณ** เปลี่ยนโหวตแล้วเครื่องหมายย้ายตาม งดออกเสียงหรือจบช่วงโหวตเครื่องหมายจะหาย รีเฟรชแล้วยังแสดงคะแนนที่ยืนยันไว้

Tab เลือกปุ่ม, Enter กด/ส่งแชต, `?` วิธีเล่น, Escape ปิดหน้าต่าง รีเฟรชแท็บเดิมเพื่อ reconnect ที่นั่งเดิม token จะถูกหมุนใหม่อัตโนมัติเมื่อกลับเข้าห้อง อย่าแชร์ session token

## Classic ตามเอกสารแนบ

| คน | หมาป่า | ผู้หยั่งรู้ | หมอ | นายพราน | ผู้อาวุโส | ชาวบ้าน |
| --- | --- | --- | --- | --- | --- | --- |
| 6 | 1 | 1 | 1 | 0 | 0 | 3 |
| 7 | 2 | 1 | 1 | 0 | 0 | 3 |
| 8 | 2 | 1 | 1 | 0 | 0 | 4 |
| 9 | 2 | 1 | 1 | 1 | 0 | 4 |
| 10 | 2 | 1 | 1 | 1 | 0 | 5 |
| 11 | 3 | 1 | 1 | 1 | 0 | 5 |
| 12 | 3 | 1 | 1 | 1 | 1 | 5 |

หมอป้องกันหมาป่า รวมตัวเองได้ ห้ามเป้าคนเดิมสองคืนติดกัน ผู้หยั่งรู้ตรวจหนึ่งคนและได้ผลเฉพาะถ้ารอดถึงเช้า จากนั้นมี 👍 (ไม่ใช่หมาป่า) / 👎 (เป็นหมาป่า) ข้างเลขที่นั่ง โดยเห็นเฉพาะผู้หยั่งรู้และคงผลเดิมหลังรีเฟรช นายพรานยิงหนึ่งครั้งภายใน 15 วินาทีเมื่อตายด้วยหมาป่าหรือประหาร ผู้อาวุโสมีเกราะต้านหมาป่า 1 ครั้ง การโหวตไม่ติดเกราะ

งดออกเสียงไม่ใช่คะแนนผู้ต้องสงสัย โหวตเสมอเปิด runoff 20 วินาที ไฮไลท์กรอบทองและป้ายผู้เข้ารอบ 2 ให้ทุกคนเห็น ส่วนคนอื่นจางลงและเลือกไม่ได้ หากยังเสมอไม่มีประหาร หมาป่าคะแนนเสมอเลือกเลขที่นั่งเป้าหมายน้อยที่สุด ไม่มีคำสั่งหมาป่า = ไม่มีโจมตี คำสั่งเปลี่ยนได้จนหมดเวลา ผู้ตายอ่านแชตได้แต่พูด/โหวตไม่ได้ ชาวบ้านชนะเมื่อหมาป่าหมด หมาป่าชนะเมื่อจำนวนไม่น้อยกว่าฝ่ายหมู่บ้าน หากไม่มีผู้รอดชีวิตจะเสมอ ตรวจผลหลังปฏิกิริยานายพรานครบแล้ว

เวลา night/discussion/vote: Quick `25/60/20`, Standard `40/120/30`, Relaxed `60/180/45` วินาที รายละเอียดการปรับจากเอกสารและส่วนที่ยังไม่เปิดอยู่ที่ [SPEC-IMPLEMENTATION.md](docs/SPEC-IMPLEMENTATION.md) ไม่มีการรับรองความสมดุลหรือเปิดจัดอันดับ

## Advanced · ทดลอง

เปิดแล้วสำหรับ **9–12 คน** ตามชุดในเอกสารแนบ เพิ่มผู้พิทักษ์เสียสละ (9 คน), แม่มดที่มียาช่วยชีวิต/ยาพิษอย่างละหนึ่งขวด (10/12 คน) และจ่าฝูงที่ผู้หยั่งรู้ตรวจว่าไม่ใช่หมาป่า (11/12 คน) เจ้าของห้องเลือกในห้องรอ กติกา ตารางบทบาท และวิธีทดลอง GM อยู่ที่ [ADVANCED.md](docs/ADVANCED.md) แม่มดมีหน้าต่าง 12 วินาทีหลังล็อกคำสั่งหลัก คนอื่นไม่เห็นเหยื่อ/จำนวนยา ไม่มีการรับรองสมดุลและยังไม่มี ranked

## Cloudflare Pages + Render

ย้ายหน้าเว็บไป Cloudflare Pages ได้โดยใช้ Render เดิม ดูขั้นตอน [ย้ายไป Cloudflare Pages](docs/CLOUDFLARE-PAGES.md) ตั้ง Build command `npm run build`, Output `dist`, Node `24` และ `PUBLIC_GAME_SERVER_URL=https://moonfall-realtime.onrender.com` จากนั้นเพิ่ม origin ใหม่ใน Render `ALLOWED_ORIGINS`

## Netlify + Render

ดูขั้นตอนสร้างบริการ ตั้งค่า URL และตรวจรับที่ **[DEPLOYMENT.md](docs/DEPLOYMENT.md)**

- `netlify.toml`: `npm run build` → `dist` กำหนด `PUBLIC_GAME_SERVER_URL` เป็น `https://moonfall-realtime.onrender.com` ใน build config แล้ว เปลี่ยนผ่าน Netlify environment settings ได้
- `render.yaml`: Node Web Service หนึ่ง instance, health `/health`, ตั้ง `ALLOWED_ORIGINS` เป็น Netlify origin
- กำหนด backend URL ผ่าน build configuration และเปลี่ยนได้ด้วย Environment variables; ไม่ใช้ Netlify Functions ถือห้องหรือ WebSocket และไม่ส่ง credentials ลง frontend
- ลิงก์เชิญเป็น URL Netlify พร้อม `?room=รหัส` แชร์ให้เพื่อนได้เมื่อ deploy และตั้งค่าสองบริการสำเร็จ

ผู้ใช้สร้าง Netlify ที่ `https://effulgent-alfajores-8367b8.netlify.app` และ Render ที่ `https://moonfall-realtime.onrender.com` แล้ว Backend ตอบ health และอนุญาต Netlify origin นี้ การใช้งานหน้าเว็บยังขึ้นกับ production deploy ล่าสุดสำเร็จ ขั้นตอน local build ไม่ได้ยืนยันสถานะ deploy จริง

## ตรวจสอบ

```sh
npm run check
npm test
npm run build
npm run test:browser
npm run test:vote
```

`check` ตรวจ syntax JavaScript ไม่ใช่ TypeScript typecheck โค้ดโปรเจกต์นี้เป็น JavaScript ไม่มี lint/formatter runner จึงไม่ได้อ้างว่ารัน lint หรือ typecheck ผ่าน

`npm test`: engine, exact presets 6–12, protection, seer, armor, Hunter reaction, draw, runoff, stale/replayed commands, 84 seeded headless games, 6-client network match, 12-client capacity, production origin allowlist (polling และ WebSocket) และ Netlify build validation

`npm run test:browser`: build static frontend และเปิดเซิร์ฟเวอร์ทดสอบเองที่พอร์ต 3210/3211 ใช้ Chromium `/usr/bin/chromium` หรือ `CHROMIUM_PATH` เล่นจริงผ่าน UI ทั้ง 6 และ 12 browser contexts แยกกันจนจบแมตช์ ตรวจลิงก์เชิญ คนที่ 13 บทบาท แชตลับ การโหวต reconnect rematch และมือถือ ภาพอยู่ใน `test-results/` (ignored)

เฉพาะเซิร์ฟเวอร์ทดสอบ `NODE_ENV=test` ใช้ `GAME_TIMER_SCALE` เร่งเวลาเพื่อให้ E2E ไม่กินเวลาหลายนาทีต่อแมตช์ Production ไม่รับตัวเร่งนี้ การทดสอบ headless ไม่ใช่หลักฐานความสมดุลจากมนุษย์

## ขอบเขต

ห้อง audit และเกมเก็บในหน่วยความจำเซิร์ฟเวอร์เดียว รีสตาร์ต/พักบริการแล้วหาย ไม่มีฐานข้อมูล สถิติระยะยาว บัญชี เสียงคุย หรือหลาย instance ผู้หลุดยังนับเป็นผู้เล่นในแมตช์ คำสั่งที่ขาดหายข้ามเมื่อหมดเวลา ทุกคนออฟไลน์เกิน 30 นาทีห้องจะถูกลบ เจ้าของห้องนำที่นั่งออฟไลน์ออกได้เฉพาะห้องรอ Advanced เปิดแบบทดลอง 9–12 คนแล้ว ส่วน Chaos/Jester ยังไม่เปิด

`npm run test:vote` เปิดเซิร์ฟเวอร์แยกที่พอร์ต 3221 และทดสอบเครื่องหมายโหวตส่วนตัวด้วย 6 browser contexts รวมเปลี่ยนเป้าหมาย งดออกเสียง reconnect และ runoff

`npm run test:lobby` ตรวจลิงก์เชิญ + Enter ในช่องชื่อ การรับช่วงเจ้าของห้องหลังทุกคนหลุด reconnect และ viewport มือถือ 320/360/390px (พอร์ต 3223)

`npm run test:hunter` เล่นแมตช์ 9 คนจนจบ ตรวจคืน AFK การโหวตส่วนตัว ผู้ตาย นายพรานยิงด้วย touch และการรอผลนายพรานก่อนชนะ (พอร์ต 3225)

สองคำสั่งข้างต้นรับ `PLAYTEST_BASE_URL` เพื่อทดสอบเว็บที่ deploy แล้วได้ จะสร้างเฉพาะห้อง QA ของตัวเอง และใช้เวลารอบจริงเมื่อทดสอบ production


## ห้องทดสอบ GM พร้อมบอท

เปิด [คู่มือ GM](docs/GM-ROOM.md) สำหรับการเปิดใช้และการควบคุม ห้องนี้แยกจากห้องปกติ มีป้าย GM TEST และต้องใช้รหัสลับของเจ้าของเซิร์ฟเวอร์ ผู้เข้าร่วมทั่วไปไม่ได้สิทธิ์ GM

- ปุ่ม `GM · ห้องทดสอบ` บนหน้าหลัก → ใส่รหัส → สร้างห้องใหม่
- คุณใช้ 1 ที่นั่ง บอทเติมส่วนที่เหลือ รวมทั้งหมด 6–12 คน
- GM เลือกบทบาทตัวเองในห้องรอได้จากชุดของโหมดและจำนวนคนปัจจุบัน หรือเลือกสุ่ม จำนวนแต่ละบทบาทยังเท่าเดิม Classic: นายพรานตั้งแต่ 9 คน ผู้อาวุโสที่ 12 คน; Advanced ดูตารางในคู่มือ
- เติม 6/9/12 คน เพิ่มบอทหนึ่งตัว ล้างบอท ดูบทบาท/คำสั่ง เร่งเวลา 5/20 เท่า จบช่วง และรีเซ็ตแมตช์ได้
- บอทใช้กติกาจริง สุ่มเป้าหมายที่ถูกต้อง หนึ่งคำสั่งต่อช่วง รวม runoff และนายพราน ไม่ใช่ AI สำหรับพิสูจน์สมดุลหรือเจรจาในแชต
- ปิดห้องโดย GM จะนำทุกคนออก หาก GM หลุดสามารถกลับด้วยแท็บเดิม สิทธิ์ไม่ย้ายไปผู้เล่นอื่น

**เปิดใช้บน Render:** ตั้ง Environment variable `GM_ADMIN_KEY` เป็นรหัสส่วนตัว 24–256 ตัวอักษร (แนะนำสุ่ม 32 ตัวขึ้นไป) แล้ว Save/redeploy รหัสนี้อยู่เฉพาะ backend ห้ามใส่ Netlify, `PUBLIC_` หรือส่งในแชต ถ้าไม่ตั้ง ห้องปกติยังเล่นได้ แต่การสร้างห้อง GM จะถูกปฏิเสธ

`npm run test:gm` เปิดเซิร์ฟเวอร์ทดสอบที่พอร์ต 3232 พร้อมรหัส fixture สำหรับเทสเท่านั้น ตรวจรหัสผิด/ถูก บอท 6/12 คน ข้อมูลลับ reconnect ความเร็ว reset และเล่นแมตช์บอทจนจบ พร้อมภาพใน `test-results/gm-room/` ไม่ต้องใช้รหัส GM จริงเพื่อรันชุดทดสอบ

`npm run test:seer` ใช้ 6 browser contexts ที่พอร์ต 3233 ตรวจผล 👍/👎 สองคืน การไม่แสดงก่อนรุ่งเช้า ความเป็นส่วนตัว reconnect และขนาด/ตำแหน่งไอคอนบนมือถือ

`npm run test:advanced` ตรวจโหมดใหม่ผ่าน static frontend แยก backend พร้อม Guard/Witch/Alpha และแมตช์จนจบ ดูรายละเอียด [ADVANCED.md](docs/ADVANCED.md)
